```text
创建商品
├── 商品名称
├── 价格
├── 库存
├── 分类
├── 商品图片 ← 新增
└── 保存

修改商品
├── 原商品信息
├── 当前商品图片 ← 可以预览
├── 更换图片 ← 可选
└── 保存

前台商品展示
├── 有图片 → 显示商品图片
└── 没有图片 → 显示本地默认图片
```

而不是：

```text
没有图片
    ↓
via.placeholder.com
```

**这个外网占位图我也建议彻底删除。**

### 我建议最终采用的行为

#### 1. 创建商品

管理员选择图片：

```text
[ 选择图片 ]
     ↓
[ 图片预览 ]
     ↓
[ 创建商品 ]
```

创建时上传图片并保存图片路径。

#### 2. 修改商品

如果已有图片：

```text
当前图片
┌──────────┐
│ 商品图片 │
└──────────┘

[ 更换图片 ]

[ 保存修改 ]
```

如果管理员不选择新图片：

> **保留原来的图片。**

如果选择新图片：

> 上传新图片，并把 `image_url` 更新成新图片。

这个行为非常重要，否则编辑商品的其他字段时，很容易把原图片误清掉。

#### 3. 没有图片

我建议不要再用在线占位图，而是：

```text
public/images/product-default.png
```

或者类似：

```text
public/images/default-product.jpg
```

前端：

```text
image_url
   │
   ├── 有 → 商品图片
   │
   └── 无 → 本地默认图片
```

这样**完全不依赖网络**。

## 这里还有一个设计问题值得提前确定

我不建议把“上传图片”和“创建商品”做成两个让用户明显感知的步骤：

```text
第一步：上传图片
第二步：复制 URL
第三步：创建商品
```

这对管理员体验很差。

应该让用户看到的就是：

```text
┌─────────────────────────────┐
│ 创建商品                    │
│                             │
│ 商品名称：[              ]  │
│ 价格：    [              ]  │
│ 库存：    [              ]  │
│ 分类：    [              ]  │
│                             │
│ 商品图片：                  │
│ ┌──────────┐                │
│ │   预览   │  [选择图片]    │
│ └──────────┘                │
│                             │
│          [创建商品]          │
└─────────────────────────────┘
```

前端实际上可以在点击“创建商品”时：

```text
创建商品
   │
   ├── 有新图片
   │      ↓
   │   上传图片
   │      ↓
   │   得到 imageUrl
   │      ↓
   │   创建商品 + imageUrl
   │
   └── 没有图片
          ↓
       创建商品
          ↓
       imageUrl = null
```

修改同理：

```text
修改商品
   │
   ├── 没换图片
   │      ↓
   │   保留原 imageUrl
   │
   └── 换了图片
          ↓
       上传新图片
          ↓
       更新 imageUrl
```

这才是比较自然的商城后台。

### 所以我会把这次改动定成一个完整的小功能

**“商品图片管理”**

范围严格控制：

* `product` 增加 `image_url`
* 创建商品表单增加图片选择/预览
* 修改商品表单增加图片预览/更换
* 后端处理图片上传
* 图片保存到本地 `uploads/products/`
* 商品保存图片访问路径
* 商品列表/详情显示图片
* 删除 `via.placeholder.com`
* 增加一个**本地默认商品图片**
* 没有图片时使用本地默认图片
* 不引入 OSS / MinIO / Nginx
